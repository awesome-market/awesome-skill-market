# Design Fusion

Rules distilled from upstream design skills by the skill-fusion pipeline. **Do not edit this file** — change `decisions/` or upstream and rebuild.

## The Floor — never ship a violation

- Identify the product, audience, and primary job from the brief or memory before designing, and confirm them with the client if the brief omits them.
- Do not accent a single word or phrase within a headline using italic, bold, or a different color.
- Do not render labels in all caps.
- Write errors that explain what went wrong and how to fix them in the interface's voice without apologizing or being vague.
- Ship responsive down to mobile, visible keyboard focus, reduced-motion respect, visual accessibility, and harmonious color palettes.

## Reflex defaults — apply unless the brief says otherwise

- Open the page with the single most characteristic element of the subject in the most appropriate form, rather than the default big-number-and-gradient treatment.
- Use one typeface family, or at most two that are clearly distinct, and never a separate display face from the body face.
- Choose non-default typefaces and set a clear type scale with intentional weights, widths, and spacing.
- When type functions as a headline or visual element, treat the type treatment itself as an active design element rather than a neutral carrier.
- Keep body line lengths under 80 characters, allowing slightly longer lines for serif body text.
- Give serif body text slightly more line-height than sans-serif body text.
- Do not add typographic labels above content unless they carry meaning.
- Use structural devices such as outlines, borders, numbering, dividers, and labels only when they encode real information about the content.
- Only add numbered markers such as 01/02/03 when the content is genuinely a sequence like a process or timeline.
- Use non-user-triggered motion sparingly and only to draw attention, favoring a single orchestrated moment over scattered effects.
- Animate transitions that answer a user action, showing what changed, rather than generic fade-and-slide-up section entrances and per-card hover effects.
- Treat copy as design content and write it with the same intentionality and minimalism applied to spacing and color.
- Name things by what users understand in plain language rather than by how the system is built.
- Use active voice by default in interface copy.
- Keep an action's name identical across the entire flow, so the button label matches the resulting status or toast.
- Treat empty screens as invitations to act rather than as mood.
- Keep copy conversational with plain verbs, sentence case, no filler, and a tone matched to the brand and audience.
- Spend boldness in one place, keeping everything else quiet and disciplined, and cut decoration that does not serve the brief.
- Do not default to a warm cream background with high-contrast serif display and terracotta or warm-clay accents unless the brief explicitly requests that direction.
- Do not default to a near-black background with a single bright acid-green or vermilion accent unless the brief explicitly requests that direction.
- Do not default to a broadsheet layout with hairline rules, zero border-radius, and dense newspaper columns unless the brief explicitly requests that direction.
- Do not default to identical rounded cards sharing one border-radius, a uniform soft grey shadow, and gradient washes as decoration unless the brief explicitly requests that direction.
- Do not apply template chrome such as tracked-out ALL-CAPS eyebrows above every heading, middle-dot meta strings, spaced-em-dash labels, tinted near-black stand-in blacks, monospace data labels, or trailing arrows on links and buttons unless the brief explicitly requests them.
- When the brief pins a visual direction, follow it exactly, including when it requests one of the generic default looks.
- Work in two passes: first produce a compact design plan covering color, type, layout, and principles, then review it against the brief before writing code.
- Revise any part of the plan that reads like the generic default for a similar brief, stating what changed and why, before writing code.
- Structure CSS selectors to avoid canceling each other out, especially between type-based and element-based selectors and between section padding and margins.
